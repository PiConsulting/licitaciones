# OBJETIVO
Extraer las causales de rechazo, desestimación, descalificación o exclusión de
ofertas. Una causal por ítem.

# ESQUEMA
{
  "causales": [
    {
      "tipo": "causal_rechazo",
      "valor": <descripción de la causal, lo más cercana posible al texto del pliego>,
      "metadata": {
        "rechazo": "automatico|sujeta_a_evaluacion|no_especificado",
        "subsanable": "si|no|no_especificado",
        "momento_aplicacion": "admision|evaluacion|adjudicacion|no_especificado"
      },
      "confidence": <número calculado según la rúbrica del sistema>,
      "source_references": [
        {
          "document_id": <valor exacto del header del fragmento>,
          "page_number": <valor exacto del header del fragmento>,
          "citation": <subcadena literal del fragmento>
        }
      ],
      "extraction_status": "success|partial|not_applicable|not_found"
    }
  ]
}

# REGLAS ESPECÍFICAS
- Una causal por ítem. Si el pliego lista incisos a), b), c), emití un ítem por inciso.
- `rechazo: "automatico"` solo si el pliego usa lenguaje imperativo sin margen de
  discrecionalidad: "será rechazada sin más trámite", "de pleno derecho",
  "causal de rechazo automático", "no será considerada".
  Si dice "podrá ser desestimada", "el organismo evaluará" → `"sujeta_a_evaluacion"`.
  Si no queda claro → `"no_especificado"`. NO lo infieras del tono.
- `subsanable`: solo `"si"` o `"no"` si el pliego lo dice de esa causal en
  particular. Una cláusula general de subsanación en otro artículo NO alcanza para
  marcar una causal específica como subsanable → `"no_especificado"`.
- `momento_aplicacion`: `admision` (apertura / control formal), `evaluacion`
  (análisis técnico-económico), `adjudicacion` (previo a adjudicar).
  Sin indicación explícita → `"no_especificado"`.
- No conviertas un requisito en causal. "Debe presentar certificado fiscal" es un
  requisito (va en otra categoría). "La falta de certificado fiscal será causal de
  rechazo" sí es una causal.
